# 桌面抓取流程

支持 wx250s 原装夹指和已配置的相机到基座标定。其他夹指、垫片或机械模型需要重新建立开口和姿态映射，不能沿用当前几何。

## 推理与筛选

1. SAM 默认输出严格物体掩码，场景定位和候选归属使用该掩码。原先默认 1 cm 的掩码膨胀不再混入物体定位结果。
2. 使用当前同步 RGB-D，排除目标附近点，拟合足够范围、接近水平的桌面。可靠拟合失败返回 `TABLE_UNAVAILABLE`；不回退到固定基坐标高度。
3. 对严格掩码、25 px 核的局部支持区域、目标框四周 35 px 上下文分别推理。每个采样点选桌面向下 30° 内的三个模型方向，重新运行第二阶段，解码所有 12 个角度和 10/20/30/40 mm 深度，保留对应的原始分数、宽度及容差。没有抬高点云或人为收窄候选开口。
4. 用正确角点构造检查 GraspNet 展示几何，并用安装的原装 STL 检查夹爪最低点到实测桌面距离。张开和闭合时均保留至少 3 mm 净空。
5. 将模型开口映射到 `left_finger` 关节范围 15–37 mm。原装接触截面包含夹指厚度，不能把两倍关节位置直接当作内侧净开口；网格接触截面约 12.1–56.1 mm。
6. 场景碰撞使用全部可见点云、3 mm 体素。每个夹指和夹爪部件分别建立保守凸包，电机转子覆盖所有转角，再检查整个 100 mm 直线进近的扫掠外形。点云表面保留 1 mm 的测量误差带：进入凸包超过 1 mm 的点判为碰撞，不再把凸包外侧 1 mm 内的点直接判为碰撞；桌面独立保留 3 mm 净空。闭合时只允许接触严格分割的目标，对其他可见点检查闭合扫掠，沿用相同误差带。诊断记录碰撞部件、点数、最大穿入量及示例点，但不能仅凭剔除数量推断旁边的碗盘挡住。保守凸包仍可能拒绝实际可行的姿态；安装的夹指和横杆 STL 存在拓扑问题，因此不依赖网格内外判断。
7. 检查夹持内部有目标点，在完整碰撞检查后进行 NMS 和排序。检查预算达到上限会记录 `budget_exhausted`；无结果不会自动放宽阈值。

工作进程只加载一次模型和夹爪网格，每个场景共享桌面和全场景点云。角度和深度解码使用向量计算；仅对通过开口、归属和桌面预筛的候选运行场景碰撞。视觉 worker 的 BLAS/OMP 使用一个 CPU 线程，避免小矩阵计算开启大量线程。

## 从推理到动作

`position` 是 GraspNet 接触参考位置，`rotation` 的 X 轴是进近方向，模型指尖在局部 X=`depth`。原装 URDF 的指尖比 `ee_gripper_link` 向前约 15.575 mm，因此末端目标为：

```text
ee_position = position + rotation[:, 0] * (depth - tip_from_ee)
pregrasp = ee_position - rotation[:, 0] * 0.10
```

该约定将真实指尖与模型指尖对齐。抓取候选恢复原来的 roll 范围 −90°~90°：若需要交换平行夹指，先对完整矩阵执行 `R @ Rx(180°)`，保持进近轴和夹持参考点不变，再对调整后的真实夹爪重新进行桌面、进近及闭合检查。不能检查原姿态后仅修改输出 r。Euler 表示在 pitch=90° 时不唯一，但传入控制器的姿态与最终受检矩阵相同。用户明确给出的 `move_arm` 朝向不做对称调整。

执行前检查场景时间戳、标定 ID、base/EE 坐标系、开口映射和流程版本。未经碰撞检查的查看结果、旧格式候选、无候选和错误坐标都不能进入高层抓放。

场景推理为工作流保留最多 8 个候选。张开夹爪前，依次只读预检候选的附近 IK、到进近位置的完整规划和保持朝向的完整笛卡尔下降；在规划状态里设置假设的张开值，不向控制器发送动作。首个候选不可达时检查下一个受检候选。预检总预算沿用 `ARM_MOTION_TIMEOUT`，全部失败返回 `NO_REACHABLE_GRASP`。具体错误保存在 attempts：求解器未返回解是 `IK_NO_SOLUTION`，已有解被限位/转角预算剔除才是 `IK_BRANCH_REJECTED`；请求或状态错误是 `IK_REQUEST_INVALID`。

执行选择后的候选时仍根据实际反馈重新规划并检查到位，再沿完整笛卡尔路径下降；不执行过期的预检轨迹，不附加固定下降量。夹爪使用候选开口，闭合按模型的 1.2 倍开口余量扣除后再内收每侧 0.5 mm，限制在关节范围内。这是位置控制，不是夹持力控制或抓取确认。

笛卡尔路径必须规划完整，沿用关节限位、累计转角、速度和近期状态检查。已计时轨迹按配置降速；无有效计时、部分路径和任何动作失败均停止，不使用旧控制器的盲目回退。撤离沿进近路径返回，保持同一朝向。无候选时不会按重心和固定朝向尝试抓取。

预检和执行都按驱动返回的关节速度限位验证计时。几何与计时有效、只有速度超限的路径，会统一延长时间到驱动限位乘 `ARM_VELOCITY_SCALING`，并同步降低速度及加速度后重新完整检查；不会提高阈值，也不会修改路径或角度。日志记录原时长、减速倍数、峰值速度，以及失败候选的 `ik` / `transit` / `descent` 阶段。

2026-10-11 的辣椒场景只读复测发现，安装的 wx250s MoveIt 配置将六个关节的 `has_velocity_limits` 设为 `false`。Humble 的 TOTG 在此分支使用默认 1 rad/s，未应用请求里的速度缩放；两个可求解候选因此超过程序的约 0.835 rad/s 检查阈值。统一减速后，两者的进近和完整下降路径均通过，肩关节峰值约 0.785 rad/s；其余六个仍返回 IK 错误码 `-31`。复测没有发送运动指令，不代表实际夹持成功。

官方依据：[Interbotix MoveIt 2 配置](https://docs.trossenrobotics.com/interbotix_xsarms_docs/ros2_packages/moveit_motion_planning_configuration.html)、[MoveIt Humble 轨迹计时](https://moveit.picknik.ai/humble/doc/examples/time_parameterization/time_parameterization_tutorial.html)、[Humble TOTG 源码](https://github.com/moveit/moveit2/blob/humble/moveit_core/trajectory_processing/src/time_optimal_trajectory_generation.cpp)。

## 参数和复现

`GRASP_CONTEXT_PX` 默认 35；`GRASP_COLLISION_BUDGET` 默认 2000；`GRASP_SCORE_MIN` 保留原默认 0。模型分数不是经过校准的成功概率。`GRIPPER_MESH_DIR` 指向已安装的原装 STL 目录。

离线诊断清单应包含 `snapshot`、`boxes` 和 `objects`；每个对象在 `objects` 中提供 `<label>_dilate0.mask_path`。也可使用保存的 `plan.json`，脚本会读取同目录 `snapshot.json` 及各物体 mask。

```bash
python3 scripts/replay_grasps.py path/to/diagnostic_input.json --output scratch/replay.json
```

脚本只启动推理 worker，不启动相机或机械臂，不检查场景过期（保存数据用于回归）。模型环境和 ROS 消息依赖由项目配置提供。逐项输出返回数量、碰撞剔除数量及预算状态，完整结果保存为 JSON；回放导出的候选标记为仅供查看。

## 实际限制

本轮只在保存的 RGB-D 上回放，没有执行机械臂抓取。点云误差带用于减少表面测量误判，不表示物理接触安全；标定误差可能远大于 1 mm，实际垫片和模型与末端的映射误差仍影响实机结果。可见点云无法证明遮挡区域没有障碍；几何筛选不验证摩擦、夹持力或物体是否被夹住。运行时仍需 MoveIt 逆解、路径规划和反馈到位检查，失败立即停止。放置目标仍使用原先的定位和高度规则，未增加容器内壁、抓持物体和放置接触的完整几何规划。
