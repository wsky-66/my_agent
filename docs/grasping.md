# 抓取流程与 RViz

抓取沿用重构前的两条路径，共用一次 RGB-D 预扫和常驻抓取模型。`GRASP_BACKEND` 可选择 `graspnet` 或 `grcnn`；GR-CNN 部署与测试见 [说明](grcnn.md)。

1. 检测、分割、定位目标和放置位置，在同一场景运行配置的模型。GraspNet 仍用原版的模型碰撞、NMS、分数和高度过滤；GR-CNN 使用 RGB-D 预测、原装夹爪开口范围与现有点云碰撞检测，不采用绝对 3 cm 高度门槛。取消后来增加的桌面拟合、STL 凸包、进近/闭合扫掠和多区域角度深度搜索。
2. **有抓取 pose**：取最高分候选，用平行夹爪对称性将 roll 调到 −90°~90°，保持进近轴不变。接触参考点按原装夹指的指尖偏移 15.575 mm 和模型 depth 转为 ee_gripper_link 目标。MoveIt 先将末端移到目标上方 10 cm，再直线降到该目标，闭合后抬到目标上方 8 cm。
3. **无抓取 pose**：默认使用定位坐标和固定姿态 `[0°,50°,0°]` 兜底。先到定位高度上方 10 cm，直线降到定位高度下方 3 cm，闭合后抬到定位高度上方 8 cm。夹爪张开 0.037 m、闭合 0.015 m，对应当前驱动的完整闭合目标；0.024 m 是部分闭合位置，可能夹不住细小物体。
4. 跨位置搬运采用 MoveIt 完整路径规划，到达放置目标上方 10 cm；终点朝向取当前实际末端朝向，不强制整个搬运过程为固定朝向的直线。放置下降到上方 4 cm，张开，控制器报告松爪成功后等待 0.5 秒，再抬到上方 10 cm。下降、抬起和放置撤离仍走笛卡尔直线，保持实际朝向。等待可以取消；松爪失败或取消后不再上升。抓取前张爪和抓取闭爪不增加等待，也不增加夹爪开口容差或稳定反馈检查。多物体只在全部完成后收拢。

工作流不再预检八个候选，也不重复计算下降路径。有 pose 但 IK/运动失败时停止；只在没有 pose 时兜底。模型加载或推理错误直接报告后端错误，不当作成功预测了零个 pose。`allow_fallback` 默认 true，明确禁用时可设为 false。结果中的 `strategies` 提供实际使用的 graspnet / grcnn / fallback。

两种模型返回 pose 后，在机械臂基座坐标系统一补偿 x −1.5 cm、z −1.0 cm，y、朝向、开口和插入深度不变。接触参考点 `position` 和末端目标 `ee_position` 同时平移，`base_offset` 记录本次补偿。RViz 候选框、所选框与实际执行目标一致；缓存及工作流不重复补偿。`.env` 中 `GRASP_OFFSET_X`、`GRASP_OFFSET_Z` 使用米，设为 0 可取消对应轴的补偿。此补偿位于模型原生筛选之后，点云和筛选输入保持原坐标；定位、兜底和放置目标沿用原值。

目标检测先按同一标签合并 IoU 至少 0.75 的重复框。多个框中，最高分至少 0.5 且第二名低于最高分一半时，选择明显占优的目标；否则保留歧义，要求明确目标。单个低分目标仍沿用原检测阈值，不因这条歧义处理规则被丢弃。原始检测保存在本机场景目录中的 `grounding.json`，计划记录候选框、分数、原始数量和选择依据；场景及诊断不加入 Git。

工作流、扫描或动作工具失败后，模型本轮只说明结果，不再调用其他工具或自行重排任务。用户补充目标后新一轮可以继续原任务顺序。场景标识不等于目录名，图像和计划路径从返回字段读取。硬件动作后清除相机快照缓存，旧 mask 的场景一致性检查继续使用。工作流完成数据中的 `execution_completed=true` 代表控制器动作序列完成；`grasp_verified=false`、`placement_verified=false` 表示没有视觉确认，回复不能断言物体已抓起或已放到目标。

过高的进近目标可能超出当前姿态下的工作空间，因此针对桌面小模型降低提起和放置进近高度，同时让跨位置搬运使用完整规划。`fraction` 是直线路径规划比例：抓取、放置下降及普通直线移动要求至少 99.9%；仅抓取后抬升 8 cm 和松爪后撤离 6 cm 两个上升步骤允许至少 95% 的有效路径，直接执行已规划的部分，不补发未规划的尾段。部分上升结果保留 `fraction` 和 `path_complete=false`，不会报告完整到达原请求高度；物理限位、避碰和轨迹计时检查继续使用。低于 95% 或规划服务报错仍停止。可用本机机器人模型离线复查目标，离线求解不等于实机验证。

选取模型 pose 时显示末端目标 z 与指尖目标 z。`ee_gripper_link` 到原装指尖沿进近轴还有 15.575 mm，因此竖直向下时指尖高度低于末端高度；GR-CNN 的表面点、插入深度、末端目标分别有不同含义。`strategies.tip_position` 记录补偿后指尖目标，不是实测到位反馈。高度补偿仍沿用 x −1.5 cm、z −1 cm；细小物体的空抓也可能来自闭爪不足，不能只靠继续降低高度处理。

## 邻近逆解与运动

旧版有朝向的移动请求没有传入实际关节初值，拿到单个逆解后直接发给关节客户端。当前使用近期实际反馈、邻近初值求解；附近无解时额外尝试中立和伸展初值。初值只用于求解，不是机械臂命令。IK 接口不提前添加转角约束，返回后选择限位内、与实际关节变化较小的分支，再由 MoveIt 规划。

执行前检查驱动物理限位、轨迹起终点、时间和速度。取消 2.6 rad 单次关节转角限制，以及 `1.5 × |终点−起点| + 0.35` 累计绕路阈值和规划附加关节约束；累计变化只记录，不拦截。累计转角是逐点绝对变化总和，不等于关节净转角或旋转圈数。不会直接将绝对关节反馈取模；有朝向的移动仍先选较近的逆解，再通过 MoveIt 规划和控制器执行。有效路径速度过高时统一延长时间；控制器报告成功就继续，下一动作只读一次当前关节位置用于规划；取消残余速度判忙及规划后关节变化复查，无额外关节到位容差、多帧稳定等待或末端误差复查。退出时的 Sleep 确认沿用退出流程。

安装的 MoveIt 2.5.9 已为笛卡尔路径完成计时（[官方服务源码](https://raw.githubusercontent.com/moveit/moveit2/2.5.9/moveit_ros/move_group/src/default_capabilities/cartesian_path_service_capability.cpp)）。下降、提起和放置直接沿用这份计时，仅在超过驱动速度目标时统一减速，不再无条件把时长乘 4。`ARM_VELOCITY_SCALING` 默认 0.25，表示驱动速度目标比例。日志的 `original_duration` 是 MoveIt 原始时长，`time_scale` 是实际减速倍数。实际耗时需在本机按完整流程测量。

## RViz

程序启动机械臂服务时会自动加载这份配置。若复用了外部已启动的服务，可单独打开：

```bash
source /opt/ros/humble/setup.bash
source ~/interbotix_ws/install/setup.bash
rviz2 -d /home/wsky/my_agent/configs/grasp.rviz
```

仓库配置使用 `wx250s/base_link` 为 Fixed Frame，包含机械臂和这些显示：

| 话题 | 内容 |
| --- | --- |
| `/graspnet/pointcloud` | 本次参与抓取推理的分割掩膜并集，剔除无效深度后的基座坐标系彩色点云；不显示背景和桌面 |
| `/graspnet/grasps` | 配置模型返回的候选，绿色夹爪轮廓、进近箭头、标签与分数；两个后端共用话题 |
| `/graspnet/selected_grasp` | 金色所选模型 pose；蓝色固定姿态兜底目标 |
| `/my_agent/ee_trajectory` | 实际下发关节轨迹经正运动学得到的连续末端点、路径细线和起终点 |
| `/move_group/display_planned_path` | 同一份最终关节轨迹，保留供 MoveIt 查看；默认不显示规划机器人动画 |

轨迹显示为不透明的连续点和细线，颜色沿时间从青色变为橙色，起终点用较大圆点标记；当前机械臂保留原外观，关闭规划机器人动画和残影。采样间隔不超过 20 ms，关节端点差较大时进一步加密到约 0.01 rad。按轨迹已有的位置、速度、加速度使用线性、三次或五次插值，然后利用 `/wx250s/robot_description` 的基座到 `ee_gripper_link` 链做批量正运动学。显示的是关节解对应的末端曲线，不是请求起终点之间的直线，也不是实际反馈测量。计算在本地进行，没有逐点 ROS FK 请求或硬件反馈等待。机器人描述异步到达时补画最近轨迹。

新运动段替换上一段，Transient Local 发布让后打开 RViz 也能收到。背景使用深色，网格间距 10 cm，视角聚焦桌面工作区域。配置增加 `End Effector Trajectory` 的 MarkerArray 显示；已有 RViz 窗口需要重新加载 `configs/grasp.rviz`。

发布者随对应 worker 常驻，使用 Transient Local 保留最后一条消息。安装的 [MoveIt 轨迹插件](https://raw.githubusercontent.com/moveit/moveit2/2.5.9/moveit_ros/visualization/rviz_plugin_render_tools/src/trajectory_visualization.cpp)使用 Volatile 订阅，因此程序在发现新的轨迹订阅者时额外发送一次最近轨迹；后打开 RViz 也能显示，订阅者不变时不会持续重播。点云仅合并已有分割掩膜，重叠区域不重复；没有掩膜则发布空点云清除旧结果，已有掩膜但无抓取 pose 时仍显示目标点云。小目标保留全部点，大点云抽样限制在 3 万点以内；这个显示处理不改变原版 GraspNet 的推理和碰撞输入。

进近箭头沿 GraspNet 的局部 X 轴，夹爪轮廓使用与 GraspNet 展示一致的四块几何，避免把夹持内部画成实心碰撞盒。新场景替换候选 marker，新选择替换所选目标 marker；所选目标会保留到下次选择。退出 worker 后销毁发布者、轨迹重发定时器和节点。

## 离线复现

```bash
python3 scripts/replay_grasps.py /tmp/my_agent_scenes/<scene>/plan.json --output scratch/replay.json
```

回放只启动推理和可视化，不启动设备或发送运动。输出候选标记为仅供查看；应重新扫描后执行。模拟验证使用 `scripts/check_motion_ros.py` 的隔离 ROS 域，不连接实际机械臂。
